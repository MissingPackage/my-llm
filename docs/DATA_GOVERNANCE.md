# Data governance

This repository does not redistribute the datasets. The configs point to remote sources and produce local artifacts that Git ignores.

The aggregate license of a web dataset does not replace reviewing the rights on the individual content. Before distributing weights or using them commercially:

1. keep the version/revision and the dataset card;
2. honor attribution obligations;
3. check applicable opt-out and takedown policies;
4. assess PII, sensitive data, illegal content, and benchmark contamination;
5. document filters and the actual mix percentages;
6. do not put secrets, company data, or personal conversations into the JSONL files.

OpenR1-Math contains problems derived from NuminaMath and synthetic traces generated by
DeepSeek-R1, then verified with Math Verify and in part with a Llama judge according to
the dataset card. Preserve this provenance: "Apache-2.0" does not turn a synthetic
solution into a provably correct proof, nor does it rule out contamination.

The preference datasets contain synthetic or human judgments that transfer bias into the model. "Aligned" means closer to those preferences, not universally correct or safe.

IT eval stack (ruling E2, 2026-07-17): evaluation-ONLY datasets — never in
training, never referenced by the configs (the same anti-contamination constraint as the
persona benchmark). Project language rule, revised by the same ruling:
the answer follows the language of the question; the reasoning trace is free
(EN expected); no metric is sacrificed for bilingualism. No corpus of
native IT traces adopted in this phase (the candidate sources remain in
the bilingual-reasoning source review).
